現在の判断

このルートは当面、LycorisフォークのGit作業ツリーとして維持します。
AxeやHKTRPGのソースをルートへ重ねず、candidates/以下の独立リポジトリとして検証します。
正式採用後に、採用版を新しい主リポジトリへ昇格させます。

現在のD:\Projects\Synchro\2026\Udonarium_synは、synchro4351/udonarium-lycorisをorigin、作者版をupstreamとするLycorisフォークです。Angularアプリ、Relayサーバー、ビルド定義、Git履歴がルート基準で構成されています。

この状態でアプリ本体をrepos/lycoris/などへ移すと、Angular設定、Docker、スクリプト、上流差分、既存ブランチが一度に変わります。採用候補が未確定の段階では、その移動リスクに見合う利点がありません。

注意: ルートに既にあるresearch/はLycoris上流の一部です。本プロジェクトの調査資料置場として使いません。本プロジェクトの文章はdoc/へ置きます。

候補検証の流れ

  1. 調査: 数分～数時間だけ読む場合は.work/<候補名>/へ浅くcloneし、終了時に削除します。
  2. 候補化: ビルドや複数回の検証へ進める候補だけをcandidates/<候補名>/へ正式cloneします。
  3. 固定: 検証開始時のコミットID、バージョン、取得日をdoc/の検証記録へ残します。
  4. 候補内検証: 依存導入、build、unit、E2Eは候補自身のディレクトリで実行します。
  5. 共通試験: 同じfixtureと合格基準をvalidation/から各候補へ適用します。
  6. 結果保存: 要約と判断はdoc/、生ログ等はvalidation/artifacts/へ分けます。
  7. 採否: 不採用候補はコミットIDと結果を資料に残してcloneを削除できます。

Gitルール

  • 候補リポジトリを親リポジトリへsubmoduleとして登録しません。採用前はローカル比較物です。
  • 候補の.git、node_modules、distを親側から追加しません。
  • 候補ごとにoriginを自分のfork、upstreamを作者版に統一します。fork前はoriginだけでも構いません。
  • 作者の既定ブランチへ直接コミットせず、ローカル検証ブランチを作ります。
  • 比較のための修正と、上流へ返せる一般修正を同じコミットに混ぜません。
  • 親のgit statusが候補の生成物で汚れないことを、各作業の終了時に確認します。

データ・秘密情報

  • SkyWay Secret、トークン、パスワード、証明書、実URLの認証情報はGitへ登録しません。
  • 実卓のZIP、立ち絵、音声、ログはvalidation/fixtures/private/またはワークスペース外へ置きます。
  • 公開fixtureには自作の小さな画像・音声・ダミーキャラクターだけを使用します。
  • 生ログは個人名、ルーム名、IP相当情報、招待URLを確認してから共有します。
  • validation/artifacts/は成果物の原本置場ではありません。重要な判断は必ずdoc/へ要約します。

正式採用時の移行

候補決定後は、採用版のリポジトリを正式な開発ルートにします。現在のLycorisルートへ別候補のファイルを上書きコピーしません。

  1. 採用版のユーザーフォークと正式ブランチを確定する。
  2. 現在の調査資料・検証計画を保存し、コミットIDを記録する。
  3. 新しい正式作業ディレクトリを用意し、採用版を通常cloneする。
  4. doc/と共通validation/の扱いを、新リポジトリへ移すか別管理にするか決める。
  5. 旧Lycoris作業ツリーは比較基準として読み取り専用で残すか、バックアップ後に削除する。
  6. VPS側のCompose・Caddyは採用版の起動方式が確定するまで変更しない。
移行は別作業: フォルダ名変更、Gitルート移動、リモート切替、旧clone削除は採用確定後に対象を再確認して行います。今回の整理では実施しません。
